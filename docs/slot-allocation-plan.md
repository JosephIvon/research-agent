## 1. 为什么现在做这件事

第九轮暴露了一个**结构性事实**（不是某条线的分数问题）：

- 8 个名额里，**90% 给了模型提名的产品**，**10% 给了 C3 通道找的产品**，
  **0% 给了纯搜索找到的产品**。
- 也就是说：管线**自己发现的**东西（L0 发现池 86–113 个候选 ✓），
  在最终名单里几乎**一个都不剩** ✗。
- 换句话说，R1（召回 0.4028）这一整套测量装置测出来的东西，
  **几乎不进入交付物** ✗。

这不是"召回不够高"的问题，是**名额分配规则**的问题 ✓。
再加召回也不会改变结果 ✓——除非名额分配改了 ✓。

## 2. 名额账实测：六个事实

（工具：`tool_slot_ledger.py`，产物：`output/recall_20261101_101613_slot_ledger.md` ✓）

| # | 事实 | 数字 | 含义 |
|---|---|---|---|
| F1 | 名额被模型提名占满 | 72/80 = **90%** 提名、8/80 = 10% C3 通道、**0** 纯搜索 | 管线自己的发现能力在交付物里几乎不出现 |
| F2 | 提名的**质量**没有闸门 | 95 次提名里 **36.8% 不在金标准**（含 ChatGPT、豆包等非赛道产品）；**闸门挡下 0 个** | "模型说是竞品"就等于"占一个名额"，没人复核 |
| F3 | `must_include`（"必须包含"）**完全失效** | 12 轮命中数 **0** | 计划里写的硬要求被静默忽略（条款是描述性文本，而代码做的是产品名的子串匹配） |
| F4 | 通道自证条目让**通道的功劳不可见** | 名额的金标准命中：含自证条目 0.76/轮 vs 主口径 0.66/轮；差额几乎全是 **筑梦岛（8/12 轮）** | 筑梦岛是赛道头部竞品，恰恰因为通道读了 aigc.cn 那一页而被剔除出分母 |

| F6 | 同分块由字母序决定 | 同分候选占比 **1.0**、最大同分块 **26**、跨名额边界同分块 **0.5/轮** | 名额归属里有"任意值"成分 |

**F1 + F2 合起来的结论**：当前名额分配实际上是
**"模型点名 → 每人一个名额 → 剩下看分数"** ✓，
而**模型的点名没有质量闸门** ✓。

## 3. MMR 的 what-if 结论（先量，再决定做不做）

工具：`tool_mmr_sim.py`（离线，同一批 12 轮的 scored 列表重放 ✓）。
相似度用的是**产品名词元的 Jaccard**（artifact 的 scored 记录没有描述字段 ⚠️）。

| 变体 | 金标准命中/轮 | 留出集 | 名册集 | C3 通道占名额 | 模型提名 | 纯搜索 |
|---|---|---|---|---|---|---|
| 现行（按分数截断） | 4.42 | 0.25 | 4.17 | 0.58 | 6.08 | **0.00** |
| MMR λ=0.8 | 4.42 | 0.25 | 4.17 | 0.58 | 6.08 | 0.00 |
| MMR λ=0.6 | 4.42 | 0.25 | 4.17 | 0.58 | 6.08 | 0.00 |
| MMR λ=0.4 | 4.42 | 0.25 | 4.17 | 0.58 | 6.08 | 0.00 |
| MMR λ=0.2 | 4.42 | 0.25 | 4.17 | 0.58 | 6.08 | 0.00 |
| MMR λ=0.6 + 提名上限 4 | 3.17 | **0.50** | 2.67 | **2.08** | 4.00 | 0.58 |
| MMR λ=0.6 + 提名上限 5 | 3.75 | **0.42** | 3.33 | **1.50** | 5.00 | 0.17 |

### 3.1 结论一：**MMR 单独做，在这个场景下是空操作**

λ 从 0.8 扫到 0.2，结果**一个数都没变** ✓。原因有二 ✓：

1. **相似度≈0**：头部产品（星野 / Character.AI / Replika / Nomi / Talkie）
   名字之间**没有任何词元重叠** ✓ → 多样性项给不出区分 ✓；
2. **更根本的**：我们要提拔的长尾产品**彼此是同赛道的近邻** ✓
   （都是"AI 角色扮演/情感陪伴" ✓），真按语义相似度算，
   多样性项**恰好会惩罚我们想提拔的那批** ✗✗。

→ 经典 MMR（用相似度做惩罚）**解决不了"名额被模型占满"这个问题** ✗。
文献里的 MMR 假设是"候选之间有冗余" ✗，我们这里的冗余不是相似性，
是**"候选已经被上游点过名"** ✗。

### 3.2 结论二：**真正能动的是"提名名额上限"，但它有明确代价**

`提名上限=5` 相对现行的得失（按品牌归一，12 轮累计）：

- **失去**：筑梦岛 7 轮、蔚蓝陪伴 6 轮、星野 4 轮 ✗（都是赛道头部 ✓）
- **得到**：AnyDoor 8 轮、Glow 6 轮、Ohai 4 轮、Cakumi 2 轮 ✓（C3 通道找到的 ✓）

代价的诚实读法 ✓：
- 头部竞品被挤掉 3–7 轮 ✗——**星野是赛道头部**，挤掉它不划算 ✗；
- 得到的 AnyDoor/Glow/Ohai **大多是通道读到的同一批页上的产品** ✓，
  而这批产品的金标准来源**正好是那些页** ✗ → 它们被"通道自证"规则剔除出分母 ✗
  （F4 ✓）→ **量测上看不到这部分收益** ✗✗。

→ 结论：**"提名上限"会改变交付物质量（大概率变差），
而现有量测口径又看不见它的收益** ✗。
**在口径没修好之前，不能动这个参数** ✗（否则就是"看不见代价地改交付物" ✗✗）。

### 3.3 结论三：名额分配的正确抓手是**上游**，不是排序器

| 抓手 | 现状 | 改动 | 风险 |
|---|---|---|---|
| **提名审计**（F2 ✓） | 36.8% 的提名不在金标准（n=95 个提名/12 轮），无人复核 | 提名要过同赛道闸门（chatgpt 这类无赛道证据的直接挡下 ✓） | 低（只挡明显的 ✗） |
| **must_include 修复**（F3 ✓） | 静默失效 ✓ | 按规范化品牌解析名单 ✓，真正强制入选 ✓ | 低 ✓ |
| **名额政策显式化**（F1 ✓） | 隐含在"+0.25 提名加权"里 ✗ | 写成一条可审计的规则（提名优先 → 证据分补位 → 同分随机 ✓） | 低（先只写清楚，不改行为 ✓） |
| **提名上限**（§3.2 ✓） | 无上限 ✓ | 可配置 ✓ | **中高**（挤掉头部 ✓）→ 口径修好前不动 ✓ |
| **MMR**（§3.1 ✓） | 无 ✓ | 做成开关 + 可插拔相似度 ✓ | 中（默认关 ✓） |

## 4. 方案

### A. 名额账常驻（纯观测，不改行为）

1. `tool_slot_ledger.py` 升级成**管线内的一份产物** ✓：
   每轮把"名额给了谁、依据是什么、挤掉了谁"写进运行记录 ✓（`slot_ledger` 字段 ✓），
   分析侧与 `tool_e2e_recall.py` 的报告合并 ✓。
2. 每轮记 **不变式**（不满足就是缺陷，直接报警 ✓）：
   - 主体自己不得占名额 ✓（当前 0 ✓）；
   - `must_include` 列出的产品必须在名单里 ✓（当前 0 ✗ → 修完必须满足 ✓）；
   - 非赛道提名不得占名额 ✓（当前有 chatgpt ✗ → 修完必须为 0 ✓）。
3. 报告里**并列两个口径** ✓：主口径（剔除通道自证条目 ✓，预注册的那个 ✓）
   与**含通道自证条目的对照口径** ✓（让通道的功劳可见 ✓，F4 ✓）。

### B. 提名审计 + must_include 修复 + 名额政策显式化（改动小、收益确定）

1. **提名审计**：被模型点名的候选要过**同赛道闸门** ✓——
   规则：提名产品若**既不在名册、也没有任何赛道词命中** → 判"非赛道" ✗ 挡下 ✓
   （普通候选仍按"未判定→放行" ✓，不误伤长尾 ✓）。
   预期效果：chatgpt 这类被挡 ✓；星野/筑梦岛这类照旧 ✓。
2. **must_include 修复**：把条款按 `、，,/ ` 拆成**产品名列表** ✓，
   用**规范化品牌**匹配 ✓，命中即**强制入选** ✓（占名额 ✓），
   并在名额账里标出"因 must_include 入选" ✓。
3. **名额政策写成一条规则**（先只写清楚、行为不变 ✓）：
   > 名额顺序 = ①计划点名且过闸门的产品 → ②其余候选按证据分（同分按种子随机 ✓）→
   > 同主机只算一家 ✓ → 满 8 个为止 ✓。
   这样"90% 归提名"就从**副作用**变成**明文规定** ✓（以后要改就改这条 ✓）。

### C. MMR 做成**开关式实验**（默认关）

1. `select_competitors` 增加 `diversity` 参数 ✓：
   `None` = 现行行为 ✓；`{"lam": λ, "similarity": "name"|"description"}` = MMR ✓。
2. **相似度可插拔** ✓：名称词元（Jaccard ✓）/ 描述词元 ✓ /
   **赛道子段标签**（LLM 打标 ✗，成本高 ✓）。
   ⚠️ 实测：名称相似度下 MMR 是空操作 ✓（§3.1 ✓）→ **描述相似度必须先量** ✗。
3. **前置条件**：artifact 的 `scored` 记录要带上**描述** ✓（现在没有 ✗）
   → 下一轮实跑才有数据能评估描述相似度的 MMR ✓。
   （这是一行改动 ✓，但要**先改再跑** ✗，否则又是一次没有数据的实验 ✗。）
4. **λ 预注册**：先定 **λ=0.7** ✓（不改 ✓）——理由：当前设置下 λ 0.8→0.2 结果全同 ✓，
   说明现阶段 λ 不敏感 ✓；等描述相似度上线后，**再按预注册的流程**决定是否调 ✓。

### 8.1 对决定 2 的收窄（有实测依据，必须说明）

决定 2 是"直接挡下"。落地前先量了一件事（`tool_mmr_sim.py` 同批产物 + 全集统计）：

- 赛道全集 289 条里，**名字**含赛道词的只有 **8%**（23 条）；
- 名字 + 证据文本含赛道词的也只有 **31%**（90 条）；
- 第九轮实际点名的产品里，`Character.AI` / `星野` / `Talkie` / `Replika` / `蔚蓝陪伴` /
  `Tofai` / `筑梦岛` / `Nomi` —— **没有一个名字里带赛道词** ✓。

⇒ 如果"没有赛道证据就挡"，**整份名单会被清空** ✗✗（实测每个提名都会被挡 ✓）。
所以收窄成两层 ✓：

| 层 | 判定 | 依据 | 影响 |
|---|---|---|---|
| **硬挡** | 通用助手品牌（chatgpt / 豆包 / 元宝 / 文心一言 / Kimi / 智谱清言 / Claude / Gemini / DeepSeek…） | **品牌名全等** ✓（不是子串 ✗，否则"ChatGPT 角色扮演"这类克隆产品会被误伤 ✓） | 决定 2 想要的"ChatGPT 这类不占名额" ✓✓ 达成 ✓ |
| **降权** | 被点名、但既不在名册、也没有任何赛道词证据 | 分数扣 0.1 ✓（提名加成 0.25 ⇒ 0.75→0.65 ✓） | 仍高于普通候选 0.5 ✓，不再稳坐前排 ✓；**不挡人** ✓ |

**并且**：反证词表原本只按"跨行业词"判（医疗/酒店/股票…），
通用助手这一类**不在里面** ✓ → 硬挡要靠**品牌全等的独立词表** ✓（`off_track_brands` ✓）。
