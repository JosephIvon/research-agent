# 竞品入选指标：为什么发现阶段只能用代理，卡在哪里，怎么闭合

> 状态：**已闭合（2026-10-29）**。第 1–6 节是当时的分析，保留原文；
> 第 7 节是闭合记录：每条做了什么、现在是什么样、还没做到什么。
> 关联：真实搜索引擎实测（`docs/decision-contract-search-e2e-2026-10.md`）。

## 1. 事实：规则说了什么，代码做了什么

计划里的准入标准是模型写的**自然语言**：

> 「直接层须满足"个人用户×AI陪伴或角色互动×移动端App"；替代层为能接管核心任务的通用AI助手……」

默认口径则是：

> 「必须有官网 + 至少 2 个维度有数据」

**代码实际执行的**（`src/workflow/research_plan.py` 的 `admit_competitors` + `score_candidate`）：

| 条件 | 代码里真的在判吗 | 在哪个阶段能判 |
|---|---|---|
| 有自己的站点 | ✅（现在是"站点类型 = 产品官网"，2026-10-28 补的） | 发现阶段 |
| 至少 2 个维度有数据 | ❌ **没有执行** | 抓完之后才有数据 |
| 必须属于某一层（direct/alternative/adjacent） | ❌ 没有执行（层只写进计划文本） | 需要语义判断 |
| 命中 must_include / must_exclude | ✅ | 发现阶段 |

**结论：计划里的准入标准目前是"描述性"的，不是"可执行"的**——报告里写着一条规则，
代码按另一套规则裁决。这不是措辞问题，是**声明与执行脱节**。

## 2. 为什么"≥2 个维度有数据"不能放在发现阶段

发现阶段手上只有搜索结果的标题/URL/摘要，**一个维度都还没抽**：
`dimension_count` 恒为 0。

上一轮踩过这个坑：把它当发现阶段的门槛 → 恒为 0 → **一家竞品都选不出来**（实测入选 0 家）。
所以现在发现阶段改用拿得到的信息：站点类型 + 词面重合 + must_include/exclude。

这不是"能力不够"，是**顺序问题**：要让"≥2 维度"当准入条件，就得先抓完候选池
（8–12 家）再决定留谁，抓取成本从 3–5 家涨到 8–12 家一轮全站爬。

## 3. 那这条规则今天在哪儿生效

| 位置 | 判什么 | 何时 |
|---|---|---|
| `competitor_matrix` 的 `content_complete` | 每行必须有有效证据 + 口径日期 + 推断标注 + 无占位 | 抓完之后 |
| evals 门禁 `matrix_completeness == 1.0` | 矩阵整体有效完整度 | 抓完之后（离线评测） |
| **准入门禁** | **没有**：抓到没数据的竞品仍然会成为矩阵里的一行（标"未核实"） | — |

所以现状是：**质量下限在事后被门禁盯着，但没有在事前把不合格的竞品踢出去**。
矩阵里可能出现"一行全是未核实"，靠门禁（离线）才发现，而不是在管线里就换人。

## 4. 闭合这个洞要做的三件事（+ 一个产品决策）

### (a) 抓后淘汰：数据不足的竞品不进矩阵

抓完某家后维度数 < 2（或 `content_complete=False`）→ 淘汰并从矩阵移除。

**需要产品决策**：
- (a1) 彻底不出现（矩阵里看不到这家）——干净，但用户看不到"我们试过它"
- (a2) 出现但标"未采信"——透明，但矩阵行数不再是"有效竞品数"
  → 我倾向 (a2) 加一行"未采信"清单，与矩阵分开：既不污染结论，又不隐藏事实。

### (b) 补位：从候选池补抓下一家

候选池**已经保留**在 `state["discovery"]["scored"]`（按分排序，含站点类型与理由），
补位的原料是现成的。缺的是"淘汰 → 补抓 → 再判"的循环，以及它与预算闸门
（`GAP_REFETCH_MAX_PAGES`）的关系。

**需要产品决策**：补位最多补几家？超预算时是"少交几家"还是"标记不完整"？
（现有 partial 语义是后者：预算收束 → `status=partial` + 前端告警。）

### (c) 让准入规则**可执行**（最关键的一条）

规则条数是有限的，可以做一个小 DSL 让代码真的执行模型写的规则：

```
必须有官网                      → site_type == product_site
至少 N 个维度有数据              → dimension_count >= N
属于 direct 层                   → 语义判断（交给模型判一次，代码只做校验）
排除 X / 必须包含 Y              → 词面匹配
```

解析不出来的规则 → 降级为默认规则，并在计划里记 `admission_rule_source=unparsed`
（**不能静默忽略**：那等于让报告里的口径变成谎言）。

这一条不需要行业知识表：规则**模式**是有限的（官网/维度数/层/包含/排除），
与"这个行业该有哪些竞品"无关。

## 5. 与本轮实测的关系

2026-10-28 真实搜索实测暴露的问题（候选池混进 36kr / cnblogs / apps.apple.com /
watcha.cn，8 个入选里只有 3 家是真官网）**正是"声明与执行脱节"的实例**：
计划里写着"必须有官网"，代码判的却是"有独立域名"——媒体站也有独立域名。
本轮已把"有官网"改成可执行的"站点类型 = 产品官网"，并补了标题级文章页判定。

但**"≥2 个维度有数据"这一条至今仍不可执行**（第 2 节的原因），
所以完整的闭合需要 (a)(b)(c) 三件事 + 一个成本决策。

## 6. 建议的推进顺序

1. **(c) 规则可执行化**（含 `admission_rule_source` 标记）——不花抓取成本，
   直接消灭"声明与执行脱节"，并让 (a) 有依据可依。
2. **(a) 抓后淘汰 + "未采信"清单**——把质量下限从事后门禁提前到管线内。
3. **(b) 补位**——最后做，因为它花钱；先量一下"被淘汰率"有多高再决定值不值。

每一步都可以单独上线、单独回滚。

# 7. 闭合记录（2026-10-29）

按第 6 节的顺序做的：**c → a → b**（先不花钱的，再花钱的）。
产品决策按第 4 节的倾向落地：(a2) 未采信清单与矩阵分开；(b) 补位封顶 2 家。

## 7.1 (c) 规则可执行化

新模块 `src/workflow/admission_rules.py`：把模型写的自然语言口径按**可观测阶段**拆开。

| 条款形态 | 落点 | 状态 |
|---|---|---|
| 「必须有官网」 | 发现阶段判 `site_type == product_site` | 可执行 |
| 「至少 N 个维度有数据」 | **抓后阶段**判（发现阶段一个维度都没抽） | 可执行（延后） |
| 「必须包含/排除 X」 | 发现阶段词面匹配 | 可执行 |
| 「属于 direct 层」 | 认得出层名，但**判不了**（要语义判断） | 记进 `not_executable`，不假装执行了 |
| 解析不出一条 | 退回默认口径（必须有官网 + 至少 2 维度），标 `source=unparsed` | 不静默忽略 |

**对齐**：规则以可执行形态进计划（`plan.admission_rule`）；
报告矩阵章节与任务描述**只拿可执行的那部分**——
报告里写的那句口径，代码判的就是它。

## 7.2 (a) 抓后淘汰 + 未采信清单

- 闸门：`_apply_admission_gate`（`src/workflow/mvp_workflow.py`）在抓取与证据合并**之后**、
  进入报告数据循环**之前**执行——被淘汰的竞品的数据**不会**进报告正文。
- 维度数不足的竞品 → `state["rejected_competitors"]`（未采信清单）。
  矩阵章节会列出它与"实际执行的入选条件"。
- 维度计数口径与打分器一致：`QualityScorer.count_dimensions(comp)`
  （同一个 DIMENSIONS/关键词表；`extraction_failed` 与非答案项不计）。

## 7.3 (b) 从留池补位

- 原料：`state["discovery"]["scored"]`（候选留池，按分排序，带站点类型与理由）。
- 只补**过了发现阶段闸门**的候选（`gate_passed` 且得分 ≥ 0.5、域名没出现过）。
- 封顶 `MAX_BACKFILL_COMPETITORS = 2`（每家一次整站爬，成本刹车）。
- 补完仍不够 → `admission_gate.met_minimum = False`，**如实写进记录**，
  不假装够了（矩阵章节与前端都会显示"未达计划下限"）。

## 7.4 现在还剩什么（不粉饰）

- **层归属仍然判不了**：模型写的"直接层须满足个人用户×移动端App"这类条件，
  代码只记下来、不据此裁决。根治要么让模型判一次（多一次调用、且模型也会错），
  要么让用户在界面上勾选——这是个产品决策，没做。
- **淘汰率还没量**：补位封顶 2 家是拍的，"被淘汰率有多高"要等真实抓取多跑几轮才知道。
- **"候选池为 0"那条路仍未走通到底**：没有竞品时下游仍然报错（该组抓取目标为空）。
  这是上一轮实测里就记下的遗留问题，本轮没碰。
- **未采信清单目前只有"抓后维度不足"这一种原因**；
  将来若加入别的淘汰理由，闸门理由是自由文本，清单不会自动分类。
