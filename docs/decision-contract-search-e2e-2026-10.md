# 决策契约：真实搜索引擎端到端（2026-10-28）

> 纪律：**判定线必须在看到数据之前写死**。看到数据后再定阈值等于给结论找理由。
> 本文件在实跑之前定稿，实跑结果另存 `output/search_e2e_*.md`，结论以本文件为准。

## 0. 为什么现在跑

上一轮把"澄清与定界层 + 搜索四段式"接进管线，但**只在替身搜索引擎下验证过**。
真链路没跑，等于"搜索质量"这件事至今没有实测依据。

更要紧的是，早前实测到过一个具体缺陷：任务句式查询（"找一下百度搭子的全部竞品信息"）
下，最该抓的**官方介绍页**与**竞品盘点页**会被相关性过滤丢掉，而媒体/百科页会被当成竞品。
新管线（先澄清 → 再按计划发短查询词）就是为修这个而做的，**但必须用真搜索引擎验证它真的修好了**。

## 1. 这次要回答的问题（Q1–Q5）与判定线

| 编号 | 问题 | 判定线（预先写死） | 不达标时的默认动作 |
|---|---|---|---|
| Q1 | 计划层能否把"百度搭子"认成具体主体 | 主体名非空 **且** `resolved_confidence ≥ 0.5` | 记为"计划层在真实模型上不可靠"；搜索按默认计划查询词跑（现有降级路径），并把"主体消歧"列为待修项 |
| Q2 | 发现质量：候选池里有多少是竞品官网 | 候选池 ≥ 5 家 **且** 入选名单中"非媒体/百科域"占比 ≥ 80% | 扩充站点类型过滤表（应用商店、导航站、电商、比价站等）；不改阈值 |
| Q3 | 任务句 vs 搜索词：管线是否对句式不敏感 | 同一主体两种句式的**入选名单 Jaccard ≥ 0.5** | 查询规划没起作用：把主体名与意图词直接拼进 entity_anchor / competitor_discovery 查询 |
| Q4 | 入选正确性：入选的是不是同一赛道 | 人工核对 ≥ 3/4 属于主体所在赛道 | 准入口径（"什么算竞品"）需要更硬的约束，或必须允许用户给竞品名单 |
| Q5 | 反证段有没有产出 | 至少 1 条 counter_evidence 结果（带 URL） | 反证查询词换法（"差评/投诉"→ 站点限定 + 产品名），或降级为"反证仅靠站内评价页" |

**不达标 ≠ 失败**：不达标时执行"默认动作"那一列，并如实记录。禁止事后调阈值。

## 2. 样本、口径与成本

- **主体 2 个**：百度搭子（用户举的例子，AI 搭子/AI 陪伴赛道）、猫箱（已知同赛道产品，做交叉对照）。
- **句式 2 种**：
  - task 句式：`找一下百度搭子的全部竞品信息`（长句、含动作词与修饰词）
  - search 句式：`百度搭子 竞品`（短搜索词）
- **共 4 组**（2 主体 × 2 句式）。不重复跑同一组取平均：搜索结果本身有抖动，
  交叉设计（2 主体 × 2 句式）比单组重复更能分辨"系统性差异"与"单次抖动"。
- **每组做**：1 次计划 LLM 调用 + 四段式搜索（entity_anchor / competitor_discovery /
  per_competitor_verify / counter_evidence，各阶段查询 ≤ 4 条）。
- **默认不整站抓取**：Q1–Q5 全部可在"搜索 + 入选"层判定，抓取只会把墙钟拉长。
  抓取链路单独跑 1 组（`--with-crawl`）做端到端确认。
- **记录字段**（每组）：计划实体与置信度与备选、每阶段查询词与结果数与去重后 URL 数、
  候选池逐条（名称/URL/是否媒体站/被打分理由）、入选逐条（分数与理由）、剔除清单、
  counter_evidence 结果条数与标题。

## 3. 已知干扰与口径边界

1. **搜索引擎结果抖动**：同一 query 两次结果不同。结论只在 4 组交叉后成立，不做单点断言。
2. **媒体站判定是启发式**（域名片段 + 路径片段），不是人工标注；Q2 的"非媒体域占比"
   以本仓库同一套判定为准，与管线行为一致（否则测的是另一套标准）。
3. **SearXNG 在本机 8888**（`.env` 的 `SEARXNG_URL`），`language=zh-CN`、`categories=general`。
   换后端（Bing/SerpAPI）结论可能不同，本轮不覆盖。
4. **计划由真实模型产出**：本轮用的就是生产默认 provider。若某组计划被拒（结构不合格），
   记为"该组走默认计划"，仍参与 Q3（默认计划也有查询词），但在 Q1 判定里单独标注。
