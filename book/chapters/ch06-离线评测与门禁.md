# 第六章 · 离线评测与门禁

## 本章能回答什么

- 20 条评测 case 怎么做到"离线、确定、可复算"。
- 夹具防篡改是怎么做的，为什么摘要必须**跨平台一致**。
- 哪些指标是硬门槛（红就是红），哪些是记录项（红了要解释）。

## 三个"离线"的前提

一次评测要能被称为"离线"，得同时满足：

1. **不触网**：站点内容来自夹具，不走真实 HTTP。
2. **不调模型**：LLM 响应来自脚本（这正是第七章那个事故的现场）。
3. **可复算**：同一份代码 + 同一份夹具，任何人跑出来数字一样。

第三条最容易被破坏——只要夹具被改过而摘要没重算，数字就会悄悄变。

## 夹具的防篡改

摘要算的是**归一化后的字节**，不是原始字节：

```python
raw = path.read_bytes()
try:
    text = raw.decode("utf-8-sig")
except UnicodeDecodeError:
    return raw  # 二进制夹具原样参与哈希
return text.replace("\r\n", "\n").encode("utf-8")
```

`research-agent@ef7204f evals/fixture_source.py:76-88`

去 BOM、CRLF→LF。函数注释里写清了为什么（`evals/fixture_source.py:79-81`）：Windows 工作区常带 BOM/CRLF、
Linux CI 是 LF，直接哈希原始字节会让两边互相误伤——**首轮 CI 就踩过这个坑**。

改夹具后必须**显式**重算，不会自动发生：

`research-agent@ef7204f evals/fixture_source.py:118`（`update_fixture_digests`）、`:126`（`manifest.json` 自身不在摘要范围内）

这一条很关键：如果"改夹具"能自动通过，防篡改就是装饰。现在改夹具 → 摘要不匹配 →
`load_manifest(verify_digests=True)` 直接抛错，必须有人显式跑 `--update-digests` 并重算基线。

## 门禁：哪几项是硬的

```python
parser.add_argument("--gate", action="store_true", help="门禁模式：安全属性硬门槛")
```

`research-agent@ef7204f evals/runner.py:542`

硬门槛只有两条，且都不接受"接近了"（`research-agent@ef7204f evals/runner.py:520` 读注入通过率、
`evals/runner.py:591` 打印通过结论）：

| 门槛 | 值 | 理由 |
|---|---|---|
| 注入通过率 | **1.00** | 安全属性不存在"99% 安全"；漏一条就是漏 |
| 全量完成 | 全部 case 都跑到终态 | 有 case 崩在中途却报"通过"，等于门禁没跑满 |

其余指标（覆盖率、扎根率、抓取削减等）是**记录项**：它们进基线、可以被讨论，
但不是"红即失败"。这个区分是本卷的立场：**安全属性用硬门槛，质量属性用趋势**。
把质量也做成硬门槛，会导致每次微小波动都红；把安全做成趋势，则是自欺。

CI 里这一条是怎么跑的：

`research-agent@ef7204f .github/workflows/ci.yml:300`（作业名）、`:317`（`python -m evals.runner --gate`）

## 基线按版本冻结，不滚动覆盖

```python
BASELINE_VERSION = "v1.7"
```

`research-agent@ef7204f evals/runner.py:24`

新增用例必须升版本并重算基线，而不是把旧基线覆盖掉
（注释原话：`# 基线与 manifest 版本同步：新增用例必须升版本并重算（不滚动覆盖历史）`）。
理由和第 3 章的截断率同构：**一个"总是被最新数据覆盖"的基线，无法回答"我们变好了还是变差了"**。

## 一次评测跑起来长什么样

```bash
uv run --extra dev python -m evals.runner --gate
```

它会逐条 case 跑完整链路（分解 → 抓取（夹具源）→ 注入清洗 → 抽取（脚本回放）→
门禁 → 报告 → 引用校验 → 重生成），把每个 case 的指标写进 `evals/results/`，
最后按门槛判定。门禁通过时的输出会点名哪条 case 是 `partial` 交付
（`research-agent@ef7204f evals/runner.py:591`）。
