# 第一章 · 定位与边界

## 本章能回答什么

- 这个产品是给**谁**用的，它替用户省掉的到底是哪一段劳动。
- 它**不**做什么——以及为什么"什么都能做"是这类产品最危险的自述。
- 为什么一份"看着很像"的调研报告，恰恰是最该被怀疑的东西。
- 把"可信"这件事拆成四个可以数的量之后，这本书后面八章分别在讲哪一个。

## 一个具体的场景

产品经理要一份竞品定价与目标用户的对比。半小时后他拿到一份排版漂亮、分点清晰、
还带一份 PRD 的报告。**报告里有一句话是错的**——某个竞品的团队版价格。

问题不在于"AI 会不会写错"。问题在于：**你没有任何办法在十分钟内找出那一句。**
这就是本卷的起点。这个产品的全部工程重量，都压在"让每一句话能被追溯"上，
而不是压在"让报告看起来更专业"上。

## 它的定位

面向产品、市场和创业团队：输入调研问题（可选竞品网站与登录凭据），系统自动完成
搜索、抓取、分析、报告生成与 PRD 生成，并在前端展示**可审计**的任务进度
（`research-agent@ef7204f README.md:9`、`research-agent@ef7204f README.md:15`）。

要看清它替用户省的是什么，得把这句话拆开：它省掉的是**搬运与整理**
（搜索、截图、抄表格、排版），**不是判断**。判断仍然在用户手里——
所以它必须把判断所需的材料（证据）一并交出来，否则省掉的那段劳动只是把风险后移。

## 它的边界

这一节比上一节重要。

**一、它不是通用 Agent 框架。** 流水线是固定的（分解 → 抓取 → 抽取 → 报告 → 校验），
ReAct 模式是一个**有界**的分支而不是万能通道：它受步数、token、美元、墙钟四重预算约束，
超了就走显式终止原因（第 2、3 章）。

**二、它不保证结论正确，只保证结论可追溯。** 这是两种不同的承诺，混为一谈就会
做出"准确率 99%"这类无法兑现的自述。它承诺的是：报告里每句事实句都挂着证据标记，
校验是确定性的、可复算的（`research-agent@ef7204f src/agent/citations.py:801`）——
**覆盖、有效、扎根**三个量分别回答"有没有引""引得对不对""引的内容支不支持这个数"。

**三、它的"完成"有灰度。** 预算耗尽时它不假装跑完：终态是 `partial` 而不是 `completed`，
且截断率单独统计（`research-agent@ef7204f evals/metrics.py:105`）。理由在第 3 章展开。

## 为什么"看着对"是陷阱

一个 AI 产品最容易通过的三道自检，恰好都不构成证据：

| 自检 | 为什么不算证据 |
|---|---|
| 演示跑通了 | 演示是**挑过的输入**，跑通只说明挑的那条路通 |
| 报告读起来专业 | 文风与事实无关；错的数字可以写在很专业的句子里 |
| 用户说"还行" | 用户没有能力核，也没有时间去核——这正是他要买的东西 |

所以这一卷的每一章都会落到同一个形式上：**一条主张 + 一个能把它判死的量 + 一条坐标**。
判不死的量（比如"体验更好"）不进这一卷。

## 可验证主张

| # | 主张 | 怎么判死 |
|---|---|---|
| 1 | 报告里的事实句带证据标记，标记是内容的哈希（内容变则 id 变），不是随手编号 | 改一个字重算 id，看是否随之变化：`research-agent@ef7204f src/agent/citations.py:168` |
| 2 | 引用覆盖度是**算出来的比值**，不是"检查过"三个字 | 公式在此：`research-agent@ef7204f src/agent/citations.py:801` |
| 3 | "被预算截断"与"跑完了"在数据模型里是两个状态，不允许被合并成一个"成功率" | 两个终态的集合定义：`research-agent@ef7204f evals/metrics.py:105` |
| 4 | 评测夹具是**可防篡改**的：改动夹具必须显式重算摘要，否则门禁红 | 摘要校验逻辑与"显式维护动作"的约定见第 6 章 |
| 5 | 文档里的数字可能落后于夹具——本书以夹具为准 | `README` 写 14 条 case（`research-agent@ef7204f README.md:23`），夹具实际 20 条（第 6 章给出核对命令） |

第 5 条不是自曝其短，而是这一卷的方法论：**账要准，落差要写出来**。
