# 第四章 · 引用校验闭环

## 本章能回答什么

- 报告里那个 `[e:1a2b3c4d5e6f]` 是怎么算出来的，为什么不是"第 1 条"这种序号。
- 四个校验量分别回答什么问题，阈值为什么是那几个数。
- 校验不过时系统做了什么——以及为什么"重生成一次仍不过"要挂标记而不是报错。

## 证据 id 为什么是哈希

```python
raw = f"{url or ''}\x00{key or ''}\x00{value or ''}".encode("utf-8")
return hashlib.sha256(raw).hexdigest()[:EVIDENCE_ID_LEN]
```

`research-agent@ef7204f src/agent/citations.py:168`（id 计算）、`:30`（长度 12 位）

三个设计点：

1. **用 NUL 分隔而不是拼接**。`a`+`bc` 与 `ab`+`c` 拼起来都是 `abc`，会算出同一个 id；
   用 `\x00` 分开就不会。
2. **内容是哈希的输入**。证据被改写后旧 id 自动失效——这是特性：一个 id 不应该同时
   代表"改写前"和"改写后"两种内容。
3. **带 url**。同一个值来自不同站点必须是两条证据；否则"跨来源佐证"就成了空话。

## 四个量，四把尺子

阈值固定在一处：

```python
DEFAULT_THRESHOLDS = {
    "citation_coverage": 0.90,
    "citation_validity": 1.00,
    "grounding": 0.90,
    "max_hallucinated_urls": 0,
}
```

`research-agent@ef7204f src/agent/citations.py:117`

| 量 | 回答的问题 | 阈值 | 为什么是这个数 |
|---|---|---|---|
| 覆盖度 | 含数字的事实句里，有多少挂了引用 | 0.90 | 留 10% 给"确实不需要引用"的句子；再松就等于允许整段不引 |
| 有效度 | 引用的 id 在证据库里有吗 | **1.00** | 引用一个不存在的 id 是硬错，没有"部分对"可言 |
| 扎根率 | 引了，但引的那条支不支持句中的数字 | 0.90 | 允许少量抽取噪声，但要求绝大多数数字可对上 |
| 幻觉 URL | 报告里出现的 URL 是否都属于实际抓过的来源 | **0** | 凭空出现的网址会直接误导读者点开 |

判定是一次性合取（`research-agent@ef7204f src/agent/citations.py:809-812`）：
四项都达线才算通过。有效度与幻觉 URL 是硬 1.00/0，另外两项才给余地。

覆盖度的公式朴素到可以手算：

```python
citation_coverage = 1.0 if not claims else cited_claims / len(claims)
```

`research-agent@ef7204f src/agent/citations.py:801`

注意 `not claims` 时返回 **1.0** 而不是 0：一份没有任何数字主张的报告，
"每个数字都有出处"这件事是平凡成立的。这个分支很容易被写反。

## 两个容易被忽略的细节

**一、附录不算主张。** 报告末尾的程序生成附录（数据完整度之类）会被先剥掉再校验，
因为那不是模型说的，不该被算成模型的断言：

`research-agent@ef7204f src/agent/citations.py:43`（剥离函数）、`:728`（校验前调用）

**二、没引用的句子分两类，但都算违规。** 一类是"真·无据断言"（该被指控），
另一类是"已识别的缺口"（模型在诚实写"这项查不到"）。两类在**呈现**上分开，
在**计数**上同样计入覆盖度：

`research-agent@ef7204f src/agent/citations.py:106`（分类）、`src/workflow/mvp_workflow.py:646-652`（呈现时分开）

这个区分不是给模型开后门——它只改"读起来像什么"，不改"通过不通过"。

## 不过之后：重生成一次，然后挂标记

违规清单不是给日志看的，是给**重生成提示词**用的：只说"不合格"没用，得指出哪句、缺什么
（`research-agent@ef7204f src/agent/citations.py:719`）。

流程是：校验不过 → 带违规清单重生成一次 → 仍不过 → **照常交付，但在报告顶部挂低可信标记**。

```python
"> ⚠️ **低可信标记：本文未通过引用完整性校验**",
f"> 引用覆盖 {citation_result['citation_coverage']:.0%}｜"
f"扎根率 {citation_result['grounding']:.0%}｜"
f"问题 {len(violations)} 处"
"（已自动重生成一次仍未通过）",
```

`research-agent@ef7204f src/workflow/mvp_workflow.py:654-660`

为什么不直接报错？因为"一句引用不实"和"整份报告不能用"是两件事，
报错会把已经抓到的证据一起扔掉。为什么不静默交付？因为一份没通过校验的报告
如果照常呈现，用户会把它当可信结论——那比报错更危险（函数注释原话，`src/workflow/mvp_workflow.py:636-637`）。

还有一个防呆设计：守卫放在函数内部（`if citation_result.get("passed"): return report`），
而不是只靠调用方判断——否则有人删掉调用处的一个 else 分支，通过的报告也会被挂上标记
（`research-agent@ef7204f src/workflow/mvp_workflow.py:639-643`）。

## 可验证主张

| # | 主张 | 怎么判死 |
|---|---|---|
| 1 | 证据 id 是内容哈希（url+key+value），不是序号 | `citations.py:168`；改一个字重算 id 会变 |
| 2 | 四个校验量的阈值写在代码里，可一处改 | `citations.py:117-122` |
| 3 | 有效度与幻觉 URL 是硬阈值（1.00 / 0） | `citations.py:119`、`:121`、`:809-812` |
| 4 | 附录被排除在校验之外 | `citations.py:43`、`:728` |
| 5 | 校验不过时**重生成一次**，仍不过则挂标记而非报错 | `mvp_workflow.py:654-660`、`:639-643` |
